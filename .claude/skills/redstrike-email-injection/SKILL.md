Run the Redstrike **email-injection** methodology (canonical spec: `skills/email-injection/`). SMTP / email header injection — the email-header variant of CRLF injection (CWE-93).

1. **Scope + approval:** read `skills/_contract/roe-gate.md` + the engagement `scope.yaml`. A probe SENDS A REAL OUTBOUND EMAIL — **get approval** + kill switch; confirm with BENIGN effects only (a single confirming send to a **tester-owned** recipient, the injected `Bcc`/`Reply-To` pointing only at a tester mailbox / OOB collector); **never** spoof or send mail to uninvolved third parties; **never** mass-mail; redact any secret the captured mail carries (reset link/token, invoice, magic-link) to a fingerprint and delete the real copy; remove any STORED payload that would re-send on a later legitimate trigger.
2. **De-dup boundary:** this skill owns the **email header manipulation** (`Bcc`/`Cc` exfil, `Reply-To` redirect, `Subject`/arbitrary override, `Content-Type`/MIME break) + its mail-layer impact. Hand off: a CR/LF that splits the **HTTP response** (response splitting / HTTP header injection) is a **different class**; reset-link host/domain control → `host-header`; dup/polluted params → `parameter-pollution`; in-page script execution → `xss-*`; the exfiltrated secret's validity/impact → `secrets` / the owning auth class. A form that merely **returns 200/accepts** a CRLF-ish payload is NOT a finding — show the injected header TOOK EFFECT.
3. **Execute:** follow `skills/email-injection/SKILL.md`; consume `<engagement>/flow-context/flow_context.json` (the actions that send a user-input-bearing email + the field that lands in the mail) + `<engagement>/js-analysis/` + `content-discovery/` (concrete forms/fields) + `scope.yaml` (`oob.collaborator` + a tester-owned recipient); work `skills/email-injection/checklist.md`; use `skills/email-injection/refs/email_injection.md`. Write outputs to `<engagement>/email-injection/`.
4. **Coverage:** copy your filled checklist into `<engagement>/email-injection/checklist.md`.
5. **Mechanical gate:** `python skills/_contract/verify_completion.py --skill skills/email-injection --out <engagement>/email-injection` → fix + re-run until exit 0.
6. **Reviewer:** launch the `email-injection-verify` subagent on `<engagement>/email-injection`. Only `accepted` findings go to reporting.
