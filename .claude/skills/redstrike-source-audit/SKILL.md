Run the Redstrike **source-audit** feeder (canonical spec: `skills/source-audit/`). White-box recon.

1. **Scope:** honor `skills/_contract/roe-gate.md` + `scope.yaml`. Requires AUTHORIZED source access (in scope). **Read-only** — grep/semgrep/secret-scan the code; **never execute it**. Redact secret VALUES to fingerprints.
2. **Execute:** follow `skills/source-audit/SKILL.md`; consume the authorized source repo + `<engagement>/js-analysis/` beautified JS + `<engagement>/web3-context/` source; work `skills/source-audit/checklist.md`; use `skills/source-audit/refs/source_audit.md`. Run the **taint-reachability pass** (`semgrep --config skills/source-audit/refs/taint/`, packs documented in `refs/taint/README.md`) and carry `taint.reachable` on each candidate — reachable = high confidence, a grep-only sink with no taint flow = low (present-but-unproven). Then run the **chain + logic reasoner** (`refs/chains/`): extract structural facts (`semgrep --config skills/source-audit/refs/chains/structural.yaml` → `structural[]`), confirm the authz absences semgrep can't (unauth-route / missing-ownership-check), and compose candidate chains per `refs/chains/patterns.yaml` into `chain_candidates[]`, each routed as an ordered executor sequence (technical taint chains + logic/authz chains). A chain is a LEAD the hunt proves leg-by-leg, never a finding here. Write outputs to `<engagement>/source-audit/` — key artifact `source_context.json` (validate against `skills/_contract/source_context.schema.json`).
3. **Coverage:** copy your filled checklist into `<engagement>/source-audit/checklist.md`.
4. **Mechanical gate:** `python skills/_contract/verify_completion.py --skill skills/source-audit --out <engagement>/source-audit` → fix + re-run until exit 0.
5. Recon feeder — **no findings, no reviewer**. Each candidate is a LEAD the routed executor must PROVE against the running target. `source_context.json` routes to `deserialization | command-injection | ssti | xss-* | sqli-* | path-traversal-lfi | prototype-pollution | xxe-* | ssrf-* | idor | privesc | fuzzing | exploit-dev`; secrets → `secrets`; dep versions → `cve-intelligence`.
