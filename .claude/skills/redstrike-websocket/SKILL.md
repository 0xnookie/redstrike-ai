Run the Redstrike **websocket** methodology (canonical spec: `skills/websocket/`). The WebSocket (WS/WSS) attack surface — CSWSH, message-layer injection over frames, authz/IDOR over frames, missing socket auth, `ws://` cleartext.

1. **Scope + approval:** read `skills/_contract/roe-gate.md` + the engagement `scope.yaml`. Opening a socket and sending frames is ACTIVE and a state-changing frame performs REAL actions — **get approval** + kill switch; confirm with BENIGN effects only (a benign READ frame for CSWSH, a benign marker / no-op frame, a benign test record reverted after); drive CSWSH from a **tester-controlled** cross-origin page against the tester's OWN session (never a real user's); TEST accounts + benign markers only; **no** message-flood / oversized-frame DoS; redact any secret the frames carry to a fingerprint; revert any test record (`cleanup.md`). If a browser is needed for CSWSH / a stateful frame write, use `skills/_contract/browser-session.md`.
2. **De-dup boundary:** this skill owns the **WebSocket break** (CSWSH, authz/IDOR over frames, missing socket auth, `ws://` cleartext, and proving a frame reaches an injection sink). Hand off: a payload that **detonates downstream** → its owning class — frame content rendered as script → `xss-*`, a SQL-backend frame → `sqli-*`, an OS-command frame → `command-injection`, a prototype-pollution JSON frame → `prototype-pollution`; CSWSH is de-duped vs `csrf` (an ordinary cross-origin HTTP form is `csrf`); TLS on `wss://` → `tls-attacks`; bare handshake-token forgery → `jwt`/`oauth`. A WebSocket endpoint that merely **upgrades (101)** is recon, NOT a finding — show a real break (accepted cross-origin read / before-after state / privileged unauth frame / cleartext capture).
3. **Execute:** follow `skills/websocket/SKILL.md`; consume `<engagement>/js-analysis/out/<site>/findings/endpoints.jsonl` (the `ws(s)://` + `new WebSocket(...)` endpoints — do NOT re-run js-analysis) + `<engagement>/auth-context/auth_context.json` (session mechanism — cookie vs token — on the handshake) + `scope.yaml` (`oob.collaborator` + ≥2 tester identities for frame-authz); work `skills/websocket/checklist.md`; use `skills/websocket/refs/websocket.md`. Write outputs to `<engagement>/websocket/`.
4. **Coverage:** copy your filled checklist into `<engagement>/websocket/checklist.md`.
5. **Mechanical gate:** `python skills/_contract/verify_completion.py --skill skills/websocket --out <engagement>/websocket` → fix + re-run until exit 0.
6. **Reviewer:** launch the `websocket-verify` subagent on `<engagement>/websocket`. Only `accepted` findings go to reporting.
