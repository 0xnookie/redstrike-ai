Run the Redstrike **lab-reconstruct** capability (canonical spec: `skills/lab-reconstruct/`). WHITE-BOX MODE ONLY.

1. **Preconditions (hard gate):** this is a WHITE-BOX capability. It requires BOTH `engagements/<id>/source/` (the target repo the framework already cloned) AND a dependency lockfile in that tree (`composer.lock`/`package-lock.json`/`yarn.lock`/`poetry.lock`/`Gemfile.lock`). If either is missing, record it in `summary.md` and emit NO lab — an absent lab is a known gap, not a clean result. No black-box facade mode in this MVP.
2. **Execute:** follow `skills/lab-reconstruct/SKILL.md`; consume `source_context.json` + the cloned `source/`, `host_discovery.json`, `cve_intel.json`, `content.json`; work `skills/lab-reconstruct/checklist.md`; use `skills/lab-reconstruct/refs/lab_reconstruct.md` (port→service matrix + base-image selection + container-safety baseline). Derive the app framework + EXACT version from the lockfile (ground truth over any banner). Emit into `<engagement>/lab/`: `Dockerfile` (app built from `source/`, deps pinned to the lockfile), `docker-compose.yml` (app + one backing service per detected open port), `lab_manifest.json` (the HONESTY LAYER — per service: recon field + confidence + `mode: white-box-exact` + `fidelity_tier`; validate against `skills/_contract/lab_manifest.schema.json`), and `README.md`.
3. **Container safety (mandatory, not optional):** the lab RUNS THE TARGET'S CODE → treat `source/` + the built container as UNTRUSTED. Loopback-only exposure (`127.0.0.1:`), NO `--privileged`/`cap_add`/host networking/docker.sock, NO real secrets baked (redacted fingerprints only; fresh benign test secrets in their place). Keep `lab/` under the engagement dir (already git-ignored via `engagements/.gitignore`) — a client-infra blueprint is never committed.
4. **IRON GUARDRAIL — the lab is NEVER an oracle:** anything developed/observed on the lab is `replica-only` (development evidence), must be RE-CONFIRMED BENIGNLY on the live authorized target before it can be a finding, and a replica NEGATIVE never marks a class exhausted. Baked into `lab_manifest.json` (`never_an_oracle: true`), restated in `lab/README.md`, and enforced at the reviewer layer by `skills/_contract/verify-base.md`.
5. **Coverage:** copy your filled checklist into `<engagement>/lab-reconstruct/checklist.md`.
6. **Mechanical gate:** `python skills/_contract/verify_completion.py --skill skills/lab-reconstruct --out <engagement>/lab-reconstruct` → fix + re-run until exit 0.
7. Review-only capability — **no findings, no reviewer, no RoE/approval gate** (the build is local + benign). It FEEDS `exploit-generator` / `exploit-dev` / `code-audit` (whose dynamic-PoC/fuzz step now has a safe local target). Each consumer treats a lab result as development-only until re-confirmed on the live target.
