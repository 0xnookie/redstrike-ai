Run the Redstrike **crlf-injection** methodology (canonical spec: `skills/crlf-injection/`). HTTP response splitting / response-header injection — the HTTP-response variant of CRLF injection (CWE-113 / CWE-93).

1. **Scope + approval:** read `skills/_contract/roe-gate.md` + the engagement `scope.yaml`. A CRLF probe is an ACTIVE test and a response SPLIT can touch a shared cache — **get approval** + kill switch; confirm with BENIGN effects only (a benign marker header such as `X-CRLF-Test`, a self-scoped `Set-Cookie` marker); **always** use a unique cache-buster so only the tester's own request is affected; **never** inject a full malicious second response a shared cache would store and serve to real users; redact any secret a captured header carries to a fingerprint.
2. **De-dup boundary:** this skill owns the **HTTP response-HEADER manipulation / response split** (injected header in the response-header block, or a parsed second `HTTP/1.x` response). Hand off: a payload that lands/executes in the response **BODY** → `xss-*` (a different class); an attacker controlling the redirect **destination/host** in `Location` without a header split → `open-redirect`/`host-header`; a poisoned response a shared cache serves **cross-user** → `cache-poisoning`; CR/LF into a generated **email** header block → `email-injection`. A request that merely **returns 200/302** after a CRLF-ish payload, or a body-only reflection, is NOT a finding — show the injected header TOOK EFFECT in the response-header block (or a real split) and that removing the CR/LF restores the normal response.
3. **Execute:** follow `skills/crlf-injection/SKILL.md`; consume `<engagement>/content-discovery/` (params + endpoints + observed response-header behaviour) + `<engagement>/injection-context/injection_context.json` (reflective sinks + injectable candidates) + `<engagement>/js-analysis/out/<site>/findings/{endpoints,params}.jsonl` (redirect/header-reflecting params) + `scope.yaml` (`oob.collaborator`); work `skills/crlf-injection/checklist.md`; use `skills/crlf-injection/refs/crlf_injection.md`. Write outputs to `<engagement>/crlf-injection/`.
4. **Coverage:** copy your filled checklist into `<engagement>/crlf-injection/checklist.md`.
5. **Mechanical gate:** `python skills/_contract/verify_completion.py --skill skills/crlf-injection --out <engagement>/crlf-injection` → fix + re-run until exit 0.
6. **Reviewer:** launch the `crlf-injection-verify` subagent on `<engagement>/crlf-injection`. Only `accepted` findings go to reporting.
